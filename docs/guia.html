a language for competitive programming

alg

alg reads like textbook pseudocode and compiles to C. You write the algorithm; it takes care of fast input, 64-bit integers, negative remainders and picking the right data structure. Every example below shows the same solution in C++ next to it, so you can see what you no longer have to write.

first

Running a program

Files use the .alg extension. The first line picks the keyword language: #lang en or #lang pt (Portuguese).

./alg sol.alg                 # compile and run; type the input
./alg sol.alg < input.txt     # or pipe a file
./alg -O -o sol sol.alg       # fast executable, no checks (to submit)
./alg -O --emit-c sol.alg     # print the generated C (judges accept it as C)

Without -O, an out-of-bounds index, a division by zero or popping an empty structure stops with the line number: erro (linha 12): índice 7 fora de 0..5 (messages are in Portuguese for now). With -O the checks go away and the code runs as fast as C.

syntax

The basics on one screen

Blocks use braces, and a single-statement body needs none, as in C. There are no types to declare: x = 5 creates a 64-bit integer. Comments start with //, a newline ends a statement and a trailing ; is optional.

Contest problems, side by side

Every alg solution here was compiled and tested against the sample input, and gives the same output as the C++ version, which is written the way contestants usually write it (with sync_with_stdio(false)).

prefix sums · O(n + q)

Range sums

Given n numbers, answer q questions "what is the sum of a[l..r]?" (1-based). Input 5 3 / 1 2 3 4 5 / 1 5 / 2 3 / 4 4 → 15 5 4.

  • #decl pre[n + 1] comes before n is read: the array is only created (zeroed) when first used.
  • Every integer is 64-bit, so the sum never overflows the way an int would.
dynamic programming · O(n · W)

0/1 knapsack

n items with weight and value, a bag of capacity W: what is the best total value? Input 4 7 / 1 1 / 3 4 / 4 5 / 5 7 → 9.

  • Counting down uses the C-style for (;;), which alg also accepts; parentheses are optional on if, while and for.
  • With -O this loop runs in 0.56× the C++ time in the project benchmark (the generated C vectorizes).
greedy + sorting · O(n log n)

Most non-overlapping activities

Each activity has a start and an end. How many can you do without overlaps? Sort by end time and take the next one that starts after the last chosen. Input 4 / 1 3 / 2 5 / 3 9 / 6 8 → 2.

  • Tuples compare field by field, like pair: (end, start) sorts by end, then by start.
  • sort uses radix sort for integers and introsort for tuples and reals: 0.46× the time of std::sort in the benchmark.
binary search on the answer · O(n log S)

Smallest truck capacity

Packages, in order, must go in at most k trips. What is the smallest truck capacity that works? Binary search on the capacity. Input 5 3 / 4 2 7 3 5 → 8.

  • Functions do not declare parameter types: the compiler infers them from the calls and emits one C version per combination of types.
  • Arrays are passed by reference, never copied: C++'s const vector<long long> & becomes just weights.
hashing · O(n) + sorted keys

How often each value appears

Read n numbers and print each distinct value with its count, in increasing order. Input 6 / 5 1 5 3 1 5 → 1 2 / 3 1 / 5 3.

  • A map is a hash table (fast like unordered_map) that iterates its keys in order (like map). You do not have to choose.
  • The hash seed changes on every run, so anti-hash tests built against unordered_map do not work here.
graph · BFS · O(n + m)

Fewest roads

Cities 1..n and m two-way roads. What is the fewest number of roads from city 1 to city n? Input 5 5 / 1 2 / 2 3 / 1 4 / 4 5 / 3 5 → 2.

  • graph(n) is undirected: edge(u, v) links both ways. Forgetting the reverse edge, a classic bug, cannot happen.
  • The graph becomes a compact adjacency array (CSR) on first query; BFS ran in 0.45× the time of the vector<vector> version.
weighted shortest path · O((n + m) log m)

Dijkstra

Directed graph with positive weights: shortest distance from city 1 to every city. Input 3 4 / 1 2 6 / 1 3 2 / 3 2 3 / 2 3 4 → 0 5 2.

  • heap() pops the smallest first: no greater<>, no negated keys. For the largest first, heap(greater).
  • INF is 1018, leaving room for INF + w. In an : int32 array the compiler stores it specially and it still reads back as INF.
  • write(dist) prints the whole array separated by spaces.
union-find · O(m log m)

Minimum spanning tree (Kruskal)

Connect all n cities with roads of minimum total cost. Sort the roads by cost and take each one that joins two separate groups. Input 4 5 / 1 2 4 / 2 3 1 / 1 3 3 / 3 4 2 / 2 4 5 → 6.

  • dsu(n) is built in (union by size + path halving): no struct to copy from your notebook.
  • d.merge(u, v) returns 1 when it joined two groups, so the loop body is a single if, and single-statement bodies need no braces.
built in

Contest techniques as functions

Techniques that show up in almost every contest are part of the language, so there is no template to paste and no classic implementation to get wrong. Ranges follow the language rule: [l, r).

linguagem para maratona de programação

alg

O alg se lê como o pseudocódigo do livro e compila para C. Você escreve o algoritmo; ele cuida da leitura rápida da entrada, do long long, do resto negativo e da estrutura de dados certa. Cada exemplo abaixo traz a mesma solução em C++ ao lado, para você ver o que deixa de escrever.

antes de tudo

Rodar um programa

O arquivo tem extensão .alg. A primeira linha diz o idioma das palavras-chave: #lang pt ou #lang en.

./alg sol.alg                 # compila e roda; digite a entrada
./alg sol.alg < entrada.txt   # ou mande um arquivo
./alg -O -o sol sol.alg       # executável rápido, sem checagens (para submeter)
./alg -O --emit-c sol.alg     # mostra o C gerado (dá para enviar ao juiz como C)

Sem -O, índice fora do vetor, divisão por zero e estrutura vazia viram erro com a linha: erro (linha 12): índice 7 fora de 0..5. Com -O essas checagens saem e o código fica tão rápido quanto C.

Problemas de maratona, lado a lado

Cada solução em alg foi compilada e testada com a entrada de exemplo e dá a mesma saída da versão em C++, escrita como um competidor escreve no dia a dia (com sync_with_stdio(false)).

soma de prefixos · O(n + q)

Soma de intervalo

Dado um vetor de n números, responda q perguntas "quanto dá a soma de a[l..r]?" (posições a partir de 1). Entrada 5 3 / 1 2 3 4 5 / 1 5 / 2 3 / 4 4 → 15 5 4.

  • #decl pre[n + 1] aparece antes de n ser lido: o vetor só é criado (zerado) no primeiro uso.
  • Todo inteiro já é de 64 bits, então a soma não estoura como estouraria com int.
programação dinâmica · O(n · W)

Mochila 0/1

n itens com peso e valor, mochila com capacidade W: qual o maior valor sem passar do peso? Entrada 4 7 / 1 1 / 3 4 / 4 5 / 5 7 → 9.

  • Para contar de trás para frente, use o para (;;) do C, que o alg também aceita; os parênteses são opcionais em se, enquanto e para.
  • Com -O, este laço roda em 0,56× o tempo do C++ no benchmark do projeto (o C gerado é vetorizado).
guloso + ordenação · O(n log n)

Máximo de atividades sem sobreposição

Cada atividade tem início e fim. Quantas dá para fazer sem sobreposição? Ordene pelo fim e pegue a próxima que começa depois da última escolhida. Entrada 4 / 1 3 / 2 5 / 3 9 / 6 8 → 2.

  • Tuplas comparam campo a campo, como pair: (fim, inicio) ordena pelo fim e desempata pelo início.
  • ordenar usa radix sort para inteiros e introsort para tuplas e reais: 0,46× o tempo do std::sort no benchmark.
busca binária na resposta · O(n log S)

Menor capacidade de caminhão

Pacotes em ordem precisam ir em no máximo k viagens. Qual a menor capacidade de caminhão que dá conta? Busca binária na capacidade. Entrada 5 3 / 4 2 7 3 5 → 8.

  • A função não declara o tipo dos parâmetros: o compilador descobre pelas chamadas e gera uma versão em C para cada combinação de tipos.
  • Vetores passam por referência, sem cópia: o const vector<long long> & do C++ vira só pesos.
hash · O(n) + chaves ordenadas

Frequência de cada valor

Leia n números e mostre cada valor distinto com quantas vezes aparece, em ordem crescente. Entrada 6 / 5 1 5 3 1 5 → 1 2 / 3 1 / 5 3.

  • O mapa é um hash (rápido como unordered_map) e percorre as chaves em ordem (como map). Você não precisa escolher.
  • A semente do hash muda a cada execução: entradas feitas para derrubar unordered_map não funcionam aqui.
grafo · BFS · O(n + m)

Menor número de estradas

Cidades 1..n e m estradas de mão dupla. Quantas estradas no mínimo da cidade 1 até a n? Entrada 5 5 / 1 2 / 2 3 / 1 4 / 4 5 / 3 5 → 2.

  • grafo(n) é não dirigido: aresta(u, v) já liga os dois lados. Esquecer a volta, um bug clássico, não acontece.
  • O grafo vira uma adjacência compacta (CSR) na primeira consulta; o BFS levou 0,45× o tempo da versão com vector<vector>.
menor caminho com pesos · O((n + m) log m)

Dijkstra

Grafo dirigido com pesos positivos: menor distância da cidade 1 até cada cidade. Entrada 3 4 / 1 2 6 / 1 3 2 / 3 2 3 / 2 3 4 → 0 5 2.

  • heap() já tira o menor primeiro: nada de greater<> nem de inverter sinal. Para o maior primeiro, heap(maior).
  • INF vale 1018, com folga para INF + w. Num vetor : int32, o compilador guarda INF de um jeito especial e ele continua valendo INF quando lido.
  • escrever(dist) escreve o vetor inteiro separado por espaço.
union-find · O(m log m)

Árvore geradora mínima (Kruskal)

Ligue as n cidades com estradas de custo total mínimo. Ordene as estradas pelo custo e pegue cada uma que junta dois grupos separados. Entrada 4 5 / 1 2 4 / 2 3 1 / 1 3 3 / 3 4 2 / 2 4 5 → 6.

  • conjuntos(n) já vem pronto (união por tamanho + compressão de caminho): nada de copiar a struct do caderno.
  • d.unir(u, v) devolve 1 quando juntou dois grupos, então o corpo do laço é um único se, e corpo de um comando só dispensa as chaves.
nativo
